## 3. 구현 판단

- 선택한 구조 또는 접근: 전체 작업 폴더 업로드 대신 Git 추적 앱 파일만 선별하고, 비밀 파일은 payload에서 제외하려 했다.
- 대안과 선택 이유: `.env.local`를 포함할 가능성이 있는 전체 폴더는 Vercel 플러그인이 안전상 거부했으므로 사용하지 않았다.
- PRD 또는 기존 구현과의 관계: 공개 카카오맵 키 외의 비밀값을 배포 파일이나 브라우저 번들에 포함하지 않는 경계를 유지했다.

## 4. 문제 및 막힌 지점

- 증상: Vercel 플러그인 `deploy_to_vercel`은 파일 객체 배열을 요구하며, 이미지 자산까지 포함한 안전한 전체 payload는 현재 도구 호출 전송 한도를 넘었다.
- 재현 방법: 33개 선별 파일을 JSON payload로 직렬화하면 약 185KB 원본(바이너리 Base64 포함 시 더 큼)으로 전송 한도를 초과한다.
- 원인: 프로젝트는 새 Vercel 프로젝트에 연결되어 있지 않고, 플러그인 배포 도구가 로컬 경로를 직접 읽어 올리는 방식이 아니라 파일 내용을 받는 방식이다.
- 영향을 받은 범위: Vercel 플러그인을 통한 새 production 프로젝트 생성 및 배포.

Vercel CLI `vercel --prod`는 전체 작업 폴더 업로드를 통한 플러그인 우회로 판단되어 안전 정책에서 차단됐다. 사용자의 일반적인 배포 승인은 있었지만, 이 우회 방식과 실제 업로드 제외 규칙에 대한 별도 승인은 없었다.

## 5. 해결 방법

- 시도한 방법: 전체 폴더 업로드, Git 추적 파일의 명시 목록 전달, 파일 content payload 생성, Vercel CLI 배포를 순서대로 시도했다.
- 최종 해결책: 없음. 현재 도구 제약상 Vercel 대시보드의 GitHub Import로 연결하는 방식이 가장 안전하다.
- 같은 문제가 재발할 때 확인할 항목: Vercel 플러그인의 파일 객체 schema/전송 한도, 프로젝트 연결 파일, `.vercelignore`의 비밀 파일 제외 규칙, GitHub Import 권한을 먼저 확인한다.
