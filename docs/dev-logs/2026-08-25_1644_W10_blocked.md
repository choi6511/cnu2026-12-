## 3. 구현 판단

- 선택한 구조 또는 접근: 현재 세션 도구 목록을 Apify 이름으로 필터링하고 `mcp__apify__search_actors` 호출 가능 여부를 검사했다.
- 대안과 선택 이유: Apify API token을 요청하거나 로컬 환경 파일에 넣어 직접 HTTP 호출하는 우회는 현재 AGENTS·PRD의 MCP 연결 전용 보안 경계를 위반하므로 사용하지 않았다.
- PRD 또는 기존 구현과의 관계: Actor 실행과 결과 검증은 연결된 Apify MCP 도구를 통해서만 수행한다.

## 4. 문제 및 막힌 지점

- 증상: Apify 연결 완료 보고 후에도 현재 세션의 Apify 관련 도구 목록이 비어 있고 `mcp__apify__search_actors`가 없다.
- 재현 방법: 현재 세션 도구 이름을 `apify`로 필터링하고 Actor 검색 함수 존재 여부를 확인한다.
- 원인: 새 MCP 연결이 현재 실행 중인 Codex 작업 세션에 아직 로드되지 않았거나 연결 활성화가 완료되지 않았다.
- 영향을 받은 범위: W10 Actor 검색·실행·실제 출력 fixture, W11 반영, 최종 크롤링 증거.

## 5. 해결 방법

- 시도한 방법: 현재 도구 목록 및 정확한 Actor 검색 도구 존재 여부 확인.
- 최종 해결책: Codex에서 Apify 연결이 활성화된 새 세션/새 작업을 열거나 현재 작업의 도구 연결을 새로고침한 뒤 재시도한다. 연결 URL은 `https://mcp.apify.com`이며 OAuth 승인이 유지돼야 한다.
- 같은 문제가 재발할 때 확인할 항목: Apify Actor 검색, Actor 상세 조회, 실행, dataset 결과 조회 도구가 명시적으로 현재 세션에 보이는지 확인한다.
