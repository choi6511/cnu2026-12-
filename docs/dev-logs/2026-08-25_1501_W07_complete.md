## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 지도에서 장소를 선택해 사진 인증·최초 획득·도감 확인까지 이어지는 P0 흐름을 회귀 검증한다.
- 실제로 완료한 범위: 모바일 세로 브라우저에서 지도, 장소 소개, 인증 입력, 이미지 압축, 최초 획득, 도감 보존, 중복 인증, 잘못된 파일 안내를 검증했다. 관련 자동 검사와 프로덕션 빌드도 재실행했다.

## 3. 구현 판단

- 선택한 구조 또는 접근: 코드를 확장하지 않고 W00–W06의 실제 사용자 흐름을 390×844 모바일 뷰포트에서 처음 상태부터 반복했다.
- 대안과 선택 이유: 단위 테스트만으로는 카카오맵 마커 이동, 버튼 비활성화, 획득 모달과 도감 연결을 함께 보장할 수 없으므로 브라우저 검증을 병행했다.
- PRD 또는 기존 구현과의 관계: GPS 요청 없이 카카오맵 마커에서 장소 소개로 이동하고, 사진은 클라이언트 압축 뒤 IndexedDB에만 저장되는 기존 보안 경계를 유지했다.

## 4. 문제 및 막힌 지점

- 증상: 브라우저 자동화에서 PowerShell이 요소 참조 표기 `@e19`를 PowerShell 변수로 해석해 첫 이동 명령이 실행되지 않았다.
- 재현 방법: PowerShell 명령에서 인용 없이 `@e19`를 사용한다.
- 원인: 셸 문법과 agent-browser 참조 문법의 충돌이다.
- 영향을 받은 범위: 자동화 명령 한 번뿐이며 앱 화면과 로컬 데이터에는 영향이 없다.

구현을 중단시킨 문제는 없었음. 의미 기반 버튼 선택으로 동일한 지도→소개→인증 시나리오를 다시 수행했다. 파일 업로드의 상대 경로는 빈 파일로 전달될 수 있어, 절대 경로를 사용해 정상 사진 선택도 재확인했다.

## 5. 해결 방법

- 시도한 방법: 스냅샷이 제공한 요소 참조를 PowerShell 명령에 그대로 전달했다.
- 최종 해결책: `find role ... --name` 의미 기반 선택과 인용된 CSS 선택자, 절대 파일 경로로 자동화를 수행했다.
- 같은 문제가 재발할 때 확인할 항목: PowerShell의 `@` 표기 인용 여부, 업로드 뒤 파일명·압축 완료 문구, Next.js 오류 오버레이 유무를 확인한다.

## 7. 미해결 사항 및 위험

- 남은 문제: 코드 회귀는 발견되지 않았다.
- 임시 처리 또는 mock: 브라우저 자동화에는 저장소의 임시 장소 이미지를 입력으로 사용했다.
- 외부 키·계정·콘텐츠 의존성: 실제 Android 카메라 촬영·카카오맵 허용 도메인·HTTPS 환경 검증은 Vercel 프로젝트 연결과 W08 배포가 필요하다.
- 다음 작업에 영향을 줄 위험: 로컬 IndexedDB는 브라우저 데이터 삭제 시 사라진다. W08의 프로덕션 브라우저에서도 최초 저장·새로고침·중복 인증을 다시 수행해야 한다.
