## 3. 구현 판단

- 선택한 구조 또는 접근: Vercel 대시보드에서 이미 연결된 GitHub 저장소 `choi6511/cnu2026-12-`와 production 도메인을 확인한 뒤, 공개 카카오맵 키만 Config 변수로 추가했다.
- 대안과 선택 이유: `SUPABASE_SECRET_KEY`, `OCTOPARSE_API_KEY`를 추가·표시·변경하지 않았다. 사용자 사진은 계속 브라우저 IndexedDB에만 저장한다.
- PRD 또는 기존 구현과의 관계: `NEXT_PUBLIC_KAKAO_MAP_KEY`는 PRD가 브라우저 공개값으로 정한 JavaScript 키이며, production 빌드가 이 값을 반영하려면 새 배포가 필요하다.

## 4. 문제 및 막힌 지점

- 증상: Vercel 플러그인의 `list_projects`는 빈 목록을, `get_project(teamId=choi6511s-projects, projectId=cnu2026-12)`는 404를 반환한다.
- 재현 방법: Vercel 플러그인에서 해당 팀/프로젝트를 조회한다.
- 원인: Vercel 대시보드 로그인 세션에는 프로젝트가 보이고 수정도 가능하지만, Codex Vercel 플러그인 연결은 같은 팀의 프로젝트를 조회하지 못하는 계정·권한 동기화 불일치 상태다.
- 영향을 받은 범위: AGENTS.md가 요구한 Vercel 플러그인 기반 최종 production 증거와 W08의 공식 완료 판정.

실제 앱·배포를 중단시킨 문제는 없었음. 다만 지정 플러그인에서 같은 프로젝트를 읽지 못하므로, 브라우저 대시보드 결과만으로 W08을 `완료`로 선언하지 않았다.

## 5. 해결 방법

- 시도한 방법: Vercel 플러그인 팀/프로젝트 조회, 인앱 브라우저 Vercel 로그인, 환경변수 저장, 대시보드 재배포, production 도메인 브라우저 검증을 수행했다.
- 최종 해결책: 실제 deployment와 product flow는 성공했다. 남은 해결책은 Codex Vercel 플러그인 연결에서 Vercel 계정/팀 권한을 새로 연결하거나 갱신하는 것이다.
- 같은 문제가 재발할 때 확인할 항목: 플러그인 `list_teams`의 team ID가 대시보드 팀과 같은지, `list_projects`에 프로젝트가 표시되는지, Vercel 연결을 해제·재연결한 뒤 `get_project` 404가 해소되는지 확인한다.
