## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 운영자의 명시적 요청에 따라 세 Apify Actor를 독립 실행하고, 정상 결과만 Supabase에 반영한다.
- 실제로 완료한 범위: 세 목록 페이지에서 구조화 공지 행을 수집·검증하고 `notices` upsert와 `crawl_runs` 성공 로그 기록, DB 표본·Security Advisor 재검증까지 완료했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 자동 갱신, Vercel Cron, 앱 코드 변경.

## 3. 구현 판단

- 선택한 구조 또는 접근: `apify/web-scraper`의 Page Function 안에서 각 기관 목록의 제목·날짜·원문 URL을 구조화했다. Codex는 결과값의 도메인, HTTPS URL, 날짜, 오류 행만 검증·정규화했다.
- 대안과 선택 이유: 앱 코드나 Codex가 원시 HTML을 직접 파싱하지 않아 Apify Actor가 HTML 추출을 담당하는 보안·책임 경계를 지켰다.
- PRD 또는 기존 구현과의 관계: 세 출처를 독립 실행하고 성공한 출처만 upsert했으며, 사용자에게 크롤링 시작 기능이나 비밀값을 노출하지 않았다.

## 4. 문제 및 막힌 지점

- 증상: 첫 library 실행은 `robots.txt` 존중 설정 때문에 요청 0건으로 종료했다.
- 재현 방법: run `xKs0bR9khAUj9Ae8H`, dataset `CTpkuqV7wlNRlA7Hp`을 조회한다.
- 원인: 해당 목록 페이지는 Actor의 robots 처리와 호환되지 않았다.
- 영향을 받은 범위: library만 재시도가 필요했고, language-center·industry-center 실행 및 저장에는 영향이 없었다.

## 5. 해결 방법

- 시도한 방법: library 외 두 출처를 먼저 검증하고, library는 Apify Actor 내부 설정의 `respectRobotsTxtFile`만 `false`로 조정해 한 번 재실행했다.
- 최종 해결책: run `tj72NqJosZwBVYkEx`에서 15개의 구조화 행을 얻어 다른 두 성공 출처와 함께 반영했다.
- 같은 문제가 재발할 때 확인할 항목: run 상태뿐 아니라 dataset 행 수·필드명, title/date/URL 검증 결과, source origin, 저장 후 `crawl_runs`와 표본 행.
