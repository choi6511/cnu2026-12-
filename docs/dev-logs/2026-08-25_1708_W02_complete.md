## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 사용자가 제공한 세 장소 사진으로 임시 대표 이미지를 교체한다.
- 실제로 완료한 범위: 중앙도서관, 국제언어교육센터, 산학연교육연구관 사진을 정적 자산으로 추가하고 각 장소 데이터가 해당 사진과 대체 텍스트를 사용하도록 변경했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 사진 편집, 장소 소개 문구·좌표 변경, 캐릭터 자산 변경은 수행하지 않았다.

## 3. 구현 판단

- 선택한 구조 또는 접근: 세 사진을 `public/places/<place-id>.jpg`로 추가하고 기존 `next/image` 렌더링 경로를 유지했다.
- 대안과 선택 이유: 화면 레이아웃과 이미지 비율이 기존 3:2 대표 영역과 맞아, 별도 크롭이나 코드상 이미지 처리 없이 원본 사진을 정적으로 제공했다.
- PRD 또는 기존 구현과의 관계: 장소 대표 이미지는 앱에 정적으로 포함되어 오프라인 지원 대상이라는 PRD 요구사항을 그대로 유지한다.

## 4. 문제 및 막힌 지점

- 증상: 초기 검사에서 의존성이 설치되지 않아 `vitest` 명령을 찾지 못했다.
- 재현 방법: 새로 복제한 저장소에서 `npm test` 실행.
- 원인: `node_modules`가 저장소에 포함되지 않기 때문이다.
- 영향을 받은 범위: 코드 변경 전후 자동 검사 실행.

구현을 중단시킨 문제는 없었음. `npm ci`로 lockfile 기준 의존성을 설치한 뒤 모든 검사를 다시 수행했다.

## 5. 해결 방법

- 시도한 방법: 기존 대표 이미지 경로와 장소 데이터의 타입 제약을 확인했다.
- 최종 해결책: 타입 제약을 JPG 경로와 `placeholder | provided` 상태로 확장하고, 제공 사진을 세 장소 ID에 맞춰 매핑했다.
- 같은 문제가 재발할 때 확인할 항목: 새 사진을 추가할 때 장소 ID와 `src/data/places.ts`의 경로·대체 텍스트가 일치하는지 확인한다.
