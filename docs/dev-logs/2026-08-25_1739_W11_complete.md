## 작업 개요

운영자가 `공지 갱신해줘`라고 요청할 때만 세 Apify 출처를 독립 실행하고, dataset 결과를 검증한 뒤 정상 결과만 Supabase에 반영하는 수동 운영 절차를 실제로 재검증했다.

## 변경 사항

- `docs/MANUAL_NOTICE_REFRESH.md`에 2026-08-25 재실행 run/dataset ID와 부분 결과를 기록했다.
- 성공 상태와 저장 성공을 분리하고, 신규 행이 0건이면 기존 공지와 마지막 성공 기록을 보존하는 규칙을 명시했다.

## 구현 판단

공지 HTML 파싱과 Actor 실행은 Apify MCP에 두고, 애플리케이션은 W10의 정규화 경계만 사용한다. 세 출처는 병렬이더라도 각각 독립 결과로 판정해 한 출처의 빈 결과가 다른 출처 저장을 막지 않도록 했다.

## 문제 및 해결

이번 재실행에서 `SUCCEEDED`인 요청도 dataset에 구조화 공지 행이 없을 수 있었다. 이를 저장 성공으로 오인하지 않고 기존 데이터를 유지하도록 운영 절차에 반영했다.
