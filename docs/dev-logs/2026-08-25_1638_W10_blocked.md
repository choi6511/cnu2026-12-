## 3. 구현 판단

- 선택한 구조 또는 접근: `https://mcp.apify.com`의 OAuth 기반 hosted MCP를 사용하고, 출처별 Actor 실행 세 개의 dataset 결과만 검증·정규화한다.
- 대안과 선택 이유: Apify API token을 프로젝트 환경 파일에 넣거나 앱에서 직접 호출하지 않는다. 학교 홈페이지 직접 `fetch`·`cheerio` 파싱도 계속 금지한다.
- PRD 또는 기존 구현과의 관계: 수동 갱신, 세 출처 독립 실행, 성공 출처만 Supabase 반영, 자동 Cron 미구현 원칙은 그대로 유지한다.

## 4. 문제 및 막힌 지점

- 증상: 현재 세션의 도구 목록에 Apify MCP Actor 검색·실행·dataset 조회 도구가 없다.
- 재현 방법: 현재 호출 가능한 도구에서 Apify 관련 도구를 확인한다.
- 원인: Codex에 `https://mcp.apify.com` 연결과 OAuth 승인이 아직 완료되지 않았다.
- 영향을 받은 범위: W10 실제 Actor 선택·실행·결과 fixture, W11 반영, 최종 크롤링 증거.

## 5. 해결 방법

- 시도한 방법: Apify 공식 MCP 문서와 제공된 URL을 확인했다.
- 최종 해결책: Codex의 MCP/커넥터 설정에서 서버 URL `https://mcp.apify.com`을 추가하고 OAuth 로그인·권한 승인을 완료한다. API token을 선택할 경우에도 채팅·Git·환경 파일에 보내지 않고 연결 자격증명에만 저장한다.
- 같은 문제가 재발할 때 확인할 항목: 연결 후 `search-actors`, Actor 상세 조회, Actor 실행, dataset 결과 조회 도구가 현재 세션에 표시되는지 확인한다.
