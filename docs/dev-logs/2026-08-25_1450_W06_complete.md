## 3. 구현 판단

- 선택한 구조 또는 접근: W05의 `getAllCollectionRecords`, `hasCollectionRecord`, `createCollectionRecord`를 재사용하고, 저장 결과가 `created`일 때만 클라이언트 모달을 연다.
- 대안과 선택 이유: 사진 Blob URL은 전체 목록에서 모두 만들지 않고 사용자가 선택한 사진에만 만들며, 전용 자식 컴포넌트에서 해제한다. 메모리 누수와 즉시 상태 변경을 피하면서 인증사진을 확인할 수 있다.
- PRD 또는 기존 구현과의 관계: 도감은 로그인 없이 이 기기 IndexedDB를 원본으로 사용한다. 현재 제공된 캐릭터 파일은 설계 시스템이 허용한 임시 자산으로 원본 변형 없이 직접 표시했다.

## 4. 문제 및 막힌 지점

- 증상: 최초 구현에서 린트가 `useEffect` 안의 동기 `setState`를 오류로 보고했다.
- 재현 방법: `npm run lint`를 실행하면 `collection-gallery.tsx`의 사진 선택 초기화 코드에서 오류가 발생했다.
- 원인: 선택된 사진 변경 시 Blob URL 상태를 effect에서 즉시 초기화하려고 했다.
- 영향을 받은 범위: 인증사진 미리보기 컴포넌트만 해당한다.

구현을 중단시킨 문제는 없었음. 브라우저 자동화 중 한 번 오래된 요소 참조가 개발 도구를 열었으나, 도구를 닫고 최신 화면 스냅샷에서 중복 인증 시나리오를 다시 수행했다. 최종 캐릭터 일러스트는 아직 임시 자산이므로 시각 품질 검증 대상에서 제외했다.

## 5. 해결 방법

- 시도한 방법: effect에서 URL과 선택 상태를 함께 갱신하는 방식을 사용했다.
- 최종 해결책: `SelectedPhotoPreview`를 `placeId` 키로 분리하고 lazy state initializer로 Blob URL을 만들며 unmount cleanup에서 `URL.revokeObjectURL`을 호출했다.
- 같은 문제가 재발할 때 확인할 항목: Blob URL 생성은 선택된 사진 하나에만 수행되는지, place 변경·컴포넌트 해제 시 URL이 해제되는지, `npm run lint`가 통과하는지 확인한다.
