## 3. 구현 판단

- 선택한 구조 또는 접근: Octoparse 플러그인의 `search_tasks({ size: 100 })`를 사용했다.
- 대안과 선택 이유: 앱 직접 크롤러, 가짜 fixture, 비대상 템플릿은 PRD·AGENTS.md의 Octoparse 전용 수집 경계를 위반하므로 만들지 않았다.
- PRD 또는 기존 구현과의 관계: 공지 HTML 요청은 Octoparse 작업 세 개만 담당한다.

## 4. 문제 및 막힌 지점

- 증상: 작업 검색 결과는 `total: 0`이다.
- 재현 방법: 연결 계정에서 `search_tasks({ size: 100 })` 실행.
- 원인: 세 학교 공지용 사용자 정의 Octoparse 작업이 아직 생성되지 않았다.
- 영향을 받은 범위: W10, W11, W12 실제 데이터 검증, W14 공지 통합, W15 최종 증거.

## 5. 해결 방법

- 시도한 방법: 기존 작업 재검색.
- 최종 해결책: 사용자 콘솔에서 세 작업을 생성한 뒤 재개한다. 작업명은 `cnu-library-notices`, `cnu-language-center-notices`, `cnu-industry-center-notices`이고, `title`, `published_at`, 절대 `url`, `collected_at`을 출력해야 한다.
- 같은 문제가 재발할 때 확인할 항목: 세 task ID, Cloud 실행 가능 상태, 성공 lot, `export_data` 결과 행.
