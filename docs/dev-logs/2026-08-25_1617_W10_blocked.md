## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 도서관, 외국어교육원, 산학협력단 공지 목록용 독립 Octoparse Cloud 작업 세 개와 실제 결과 기반 필드 매핑을 구성한다.
- 실제로 완료한 범위: 현재 Octoparse 연결, 기존 작업 목록, 공지 목록 추출용 Cloud 템플릿의 사용 가능 여부를 실제로 확인했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 세 작업 생성, 실행 결과 저장, 실제 결과 fixture 및 `NoticeInput[]` 정규화 검증은 사용자 계정에서 범용 작업 편집/생성 권한 또는 대상 템플릿이 제공될 때까지 보류한다.

## 3. 구현 판단

- 선택한 구조 또는 접근: Octoparse 플러그인의 실제 작업/템플릿 API를 먼저 조사한 뒤, 세 출처별로 제목·날짜·원문 URL·수집 시각을 확보할 수 있는 Cloud 템플릿만 사용한다.
- 대안과 선택 이유: 범용 `smart-article-scraper` 등으로 목록 URL 하나를 처리하는 방식은 개별 공지 행의 제목·날짜·원문 URL을 보장하지 못한다. 홈페이지 직접 `fetch`·`cheerio` 파서는 AGENTS.md에서 금지했으므로 채택하지 않았다.
- PRD 또는 기존 구현과의 관계: PRD의 출처 세 곳과 W10의 “실제 Octoparse 결과 기반 필드 매핑” 조건을 그대로 유지했다.

## 4. 문제 및 막힌 지점

- 증상: 연결된 Octoparse 계정에 기존 작업이 없으며(`search_tasks`: total 0), 제공된 템플릿 검색 결과에도 충남대 세 공지 목록을 행 단위로 추출할 수 있는 Cloud 템플릿 또는 범용 작업 작성 기능이 없다.
- 재현 방법: `search_tasks({ size: 100 })`와 `search_templates`로 한국 대학 공지 목록/범용 목록 추출 Cloud 템플릿을 검색한다.
- 원인: 현재 플러그인은 기존 작업 실행·결과 내보내기와 사전 제작 템플릿 실행 API만 제공한다. 대상 학교별 선택자와 출력 필드를 지정하는 사용자 정의 Octoparse 작업 편집 기능이 연결되어 있지 않다.
- 영향을 받은 범위: W10 완료 조건 전체와 W11의 결과 검증·Supabase 반영 구현이 선행 조건 부족으로 진행될 수 없다.

## 5. 해결 방법

- 시도한 방법: 기존 작업 검색, “Korean university website bulletin board notice list title publication date original URL” 및 범용 목록 추출 템플릿 검색을 실행했다.
- 최종 해결책: 임의 템플릿 또는 직접 파서를 사용하지 않고 W10을 막힘으로 남긴다. Octoparse 웹 콘솔에서 아래 작업을 만들거나, 해당 작업을 생성·편집할 수 있는 플러그인 권한을 연결한 뒤 재개한다.
  - `cnu-library-notices`: `https://library.cnu.ac.kr/bbs/list/1`
  - `cnu-language-center-notices`: `https://dream.cnu.ac.kr/bbs/list.php?wcode=02`
  - `cnu-industry-center-notices`: `https://iuc.cnu.ac.kr/iuc/customer/notice.do`
  - 각 작업의 출력 필드: `title`, `published_at`, `url`(절대 URL), `collected_at`
- 같은 문제가 재발할 때 확인할 항목: 생성된 세 작업의 Octoparse `taskId`, Cloud 실행 가능 상태, 최근 성공 lot, `export_data`로 읽을 수 있는 실제 결과 행을 확인한다.
