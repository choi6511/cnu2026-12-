## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 브라우저에서만 초기화되는 Kakao 지도, 충남대학교 대덕캠퍼스 중심의 세 고정 마커와 장소 라벨, 장소 소개 이동, SDK 오류·오프라인 안내를 구현하고 실제 온라인 Chrome에서 검증한다.
- 실제로 완료한 범위: 공식 충남대학교 캠퍼스맵의 세 좌표를 정적 장소 데이터에 반영하고, Kakao SDK Client Component, 최소 전역 타입, 마커·라벨·이동 처리, 지도 로딩·키 누락·SDK 오류·오프라인 상태 UI를 구현했다. 타입 검사·린트·빌드와 오류·오프라인 브라우저 경로를 검증했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 저장된 키가 Kakao Admin 키여서 JavaScript SDK가 401을 반환했다. 실제 지도 타일, 세 마커, 마커/라벨 클릭 이동의 성공 경로는 올바른 JavaScript 키로 교체한 뒤 같은 W03에서 이어서 검증해야 한다.

## 3. 구현 판단

- 선택한 구조 또는 접근: 홈 Server Component는 공개 지도 키와 `id`, `shortName`, `coordinates`만 직렬화해 지도 Client Component에 전달한다. Client Component는 `next/script`의 `afterInteractive`와 Kakao 공식 `autoload=false`·`kakao.maps.load` 흐름으로만 SDK를 초기화한다.
- 좌표 근거: 충남대학교 공식 캠퍼스맵 `content.xml`의 건물 항목을 직접 확인했다.
  - 중앙도서관 N1 (`d_14`): `36.370140, 127.346035`
  - 국제언어교육센터 E1-1 (`d_26`): `36.362356, 127.345809`
  - 산학연교육연구관 W1 (`d_19`): `36.365326, 127.344491`
  - 출처: `https://plus.cnu.ac.kr/js/cyber/xmls/content.xml`, 건물 대응 확인: `https://plus.cnu.ac.kr/html/cyber/cyber.html`
- SDK 근거: Kakao 공식 Web API 가이드의 JavaScript 키·등록 도메인 요구와 동적 로드 문서, Marker click 이벤트 샘플을 따랐다.
  - `https://apis.map.kakao.com/web/guide/`
  - `https://apis.map.kakao.com/web/documentation/`
  - `https://apis.map.kakao.com/web/sample/addMarkerClickEvent/`
- 상태 구조: `navigator.onLine`은 `useSyncExternalStore`로 구독하고 지도 생명주기 상태와 조합해 `loading`, `ready`, `offline`, `missing-key`, `error`를 렌더 중 파생한다. effect 내부 동기 상태 갱신을 피하고 전역 이벤트 리스너를 정리한다.
- 이동 구조: 지도 마커와 DOM 버튼 기반 CustomOverlay 라벨이 같은 장소 이동 함수를 사용한다. 라벨은 키보드로 조작 가능한 실제 `button`이며 아래의 정적 장소 링크는 지도 실패 시에도 남는다.
- PRD 또는 기존 구현과의 관계: GPS·QR·AI 판별은 추가하지 않았다. 지도 SDK만 외부 네트워크에 의존하며 W02 장소 소개와 정적 목록은 그대로 유지했다.

## 4. 문제 및 막힌 지점

- 증상: 키 저장 후 모바일 브라우저에서 `.campus-map-shell` 상태가 `error`, 지도 타일 0개, 라벨 0개로 확인됐다.
- 재현 방법: `npm run dev` 후 agent-browser 320×800에서 `/`을 열고 Kakao SDK 요청 및 전역 객체를 검사했다.
- 원인: 키 값을 출력하지 않는 별도 요청 검사에서 Kakao SDK가 HTTP 401과 `appKeyType is ADMIN_KEY. but expected [NATIVE_APP_KEY, JAVASCRIPT_KEY]`를 반환했다. `.env.local`에는 Admin 키가 저장되어 있다.
- 영향을 받은 범위: 온라인 지도 타일, 세 마커·라벨 표시, 지도 요소 클릭 이동의 성공 검증만 막혔다. 정적 장소 목록과 오류·오프라인 안내는 정상이다.
- 추가 경계: agent-browser의 네트워크 목록 명령이 SDK 요청 URL의 공개 키 쿼리를 출력할 수 있음을 확인했다. 이후에는 `.env.local` 값을 내부 변수로 읽고 응답에서 키를 치환한 진단만 사용해야 한다.

## 5. 해결 방법

- 시도한 방법: SDK script 존재, `window.kakao`, 관련 리소스, 콘솔·오류 오버레이를 확인했다. 스크립트 요소와 요청은 있었지만 `window.kakao`가 생성되지 않았고 콘솔 오류는 없었다.
- 최종 해결책: 코드 실패가 아닌 자격증명 종류 오류로 확정했다. 사용자가 Kakao 개발자 콘솔의 JavaScript 키로 `.env.local`의 `NEXT_PUBLIC_KAKAO_MAP_KEY` 값만 교체하고 `http://localhost:3000`을 JavaScript SDK 도메인에 등록해야 한다.
- 독립적으로 해결한 코드 문제: 첫 구현은 effect에서 온라인·지도 상태를 동기 갱신해 React 19 린트에 걸렸다. 온라인 상태를 `useSyncExternalStore`로 바꾸고 지도 상태를 파생해 린트를 통과했다.
- 같은 문제가 재발할 때 확인할 항목: 키 값을 출력하지 말고 SDK 응답의 HTTP 상태와 `errorType/message`만 확인한다. JavaScript 키 종류, 정확한 로컬/프로덕션 도메인 등록, 개발 서버 재시작을 차례로 점검한다.

## 7. 미해결 사항 및 위험

- 남은 문제: JavaScript 키로 교체하고 로컬 도메인을 등록한 뒤 지도 타일, 세 마커·라벨, 각 장소 클릭 이동을 실제 브라우저에서 검증해야 한다.
- 임시 처리 또는 mock: 지도는 mock하지 않았다. SDK 실패를 실제 실패 상태로 표시한다.
- 외부 키·계정·콘텐츠 의존성: Kakao 개발자 콘솔의 JavaScript 키와 `http://localhost:3000` JavaScript SDK 도메인 등록이 필요하다. Vercel 배포 시 프로덕션 HTTPS 도메인도 추가해야 한다.
- 다음 작업에 영향을 줄 위험: W03이 완료되지 않았으므로 W04로 완료 순서를 넘기지 않는다. 올바른 키를 받은 뒤 같은 작업을 재개한다.
- 보안·운영 주의: JavaScript 키는 브라우저에 공개되는 키이지만 등록 도메인으로 사용 범위를 제한해야 한다. Admin 키는 절대 `NEXT_PUBLIC_` 환경변수에 두지 않는다.
