## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 사용자 제공 CHA-CHA 브랜드 시트에 있는 원본 마스코트만 PWA에 표시하도록 정리한다.
- 실제로 완료한 범위: 홈, 도감, 장소별 첫 획득 연출, 획득 카드의 보이는 마스코트를 하나의 공식 원본-자산 컴포넌트로 교체했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 장소별 새 의상·소품 파생 일러스트 제작, Vercel 프로젝트 소유자 계정에서의 배포 대시보드 조작은 하지 않았다.

## 3. 구현 판단

- 선택한 구조 또는 접근: `ChachaMascot` 컴포넌트가 `CHA-CHA)Design System/assets`의 정적 원본 파일만 import하고, 장소 ID에서 공식 포즈로 결정한다.
- 대안과 선택 이유: 새 캐릭터를 다시 그리거나 이미지 생성 모델로 수정하지 않았다. 사용자 제공 원본 시트와 저장소의 `brand-sheet.png` SHA-256이 `989A9A934310F1FC2195846072750498D057F6C4B41AFB8D0A949023BF6F1A56`로 동일했고, 정확한 원본을 그대로 쓰는 방식이 PRD의 재색칠·회전·반전·왜곡 금지 조건을 가장 안전하게 만족한다.
- PRD 또는 기존 구현과의 관계: 세 장소의 수집 흐름, IndexedDB 저장, 사진 처리와 데이터 모델은 바꾸지 않았다. 표현만 `library → studying`, `language-center → running`, `industry-center → cheering`으로 바꿨다.

## 4. 문제 및 막힌 지점

- 증상: 첫 전체 검증 중 별도의 동시에 실행된 `next build`가 이미 실행 중이라는 메시지가 한 번 발생했다.
- 재현 방법: 같은 작업 디렉터리에서 빌드를 중복 시작한다.
- 원인: 이전 검증 실행이 완료되기 전에 중복 빌드를 요청했다.
- 영향을 받은 범위: 코드·생성물에는 영향이 없었고, 빌드 잠금이 사라진 뒤 단일 빌드를 다시 실행했다.

## 5. 해결 방법

- 시도한 방법: 생성물과 실행 중인 Node 프로세스를 읽기 전용으로 확인했다.
- 최종 해결책: 다른 활성 프로젝트의 `localhost:3000` 프로세스는 건드리지 않고, 대상 프로젝트의 중복 빌드가 끝난 뒤 단독 빌드가 성공하는 것을 확인했다.
- 같은 문제가 재발할 때 확인할 항목: `.next-build/lock`, 같은 저장소의 `next build` 프로세스, 그리고 OneDrive 외부의 관련 없는 개발 서버를 먼저 구분한다.

## 7. 미해결 사항 및 위험

- 남은 문제: 공유 Vercel 프로젝트는 다른 팀원 소유여서 이 세션의 Vercel 연결 도구에서는 직접 프로젝트 상태를 조회·재배포할 수 없다.
- 임시 처리 또는 mock: 기존 `public/characters/*.webp`는 하위 호환 파일로 남아 있지만, 이 변경 후 보이는 PWA 마스코트 경로에서는 import하지 않는다.
- 외부 키·계정·콘텐츠 의존성: GitHub main 병합 후 공유 저장소에 연결된 Vercel의 자동 배포 전파를 외부 URL에서 확인해야 한다.
- 다음 작업에 영향을 줄 위험: 원본 마스코트에는 임의 변형 CSS(회전·좌우 반전·재색칠)를 추가하지 않는다.
