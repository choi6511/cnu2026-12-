## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: Apify 연결이 복구됐는지 재확인하고, 가능하면 세 출처 공지를 갱신한다.
- 실제로 완료한 범위: 현재 도구와 MCP 서버 목록, 로컬 Codex MCP 등록 상태를 읽기 전용으로 확인했다.
- 범위에서 제외하거나 다음으로 넘긴 것: Apify Actor 실행과 Supabase 반영은 현재 세션에 Apify 도구가 없어 수행하지 못했다.

애플리케이션 코드, Apify 실행 상태, Supabase 데이터는 변경하지 않았다.

## 3. 구현 판단

- 선택한 구조 또는 접근: Apify MCP가 실제 도구 목록에 나타나는지를 성공 기준으로 삼았다.
- 대안과 선택 이유: 로컬 설정에 서버가 등록돼 있다는 사실만으로 실행 가능하다고 판단하지 않았다. 현재 세션의 MCP 초기화 결과가 실제 실행 가능 여부를 결정하기 때문이다.
- PRD 또는 기존 구현과의 관계: 자체 크롤러나 Octoparse로 대체하지 않고 Apify 전용 경계를 유지했다.

## 4. 문제 및 막힌 지점

- 증상: 현재 도구 목록에서 Apify 도구가 0개이며, MCP 리소스에 노출된 서버는 `codex_apps`, `octoparse`뿐이다.
- 재현 방법: 현재 세션의 도구 목록에서 `apify`를 검색하고 MCP 리소스 서버명을 확인한다.
- 원인: 로컬 `~/.codex/config.toml`에는 `[mcp_servers.apify]`, `enabled = true`, `url = "https://mcp.apify.com"`가 존재하지만 현재 실행 중인 Codex 세션이 서버를 초기화하지 못했다. 직전 기록의 OAuth `invalid_grant`와 일치하는 상태다.
- 영향을 받은 범위: Actor 실행, dataset 조회, 정규화, 신규 공지 upsert, 신규 `crawl_runs` 기록.

## 5. 해결 방법

- 시도한 방법: 도구 전체 검색, MCP 리소스 조회, 로컬 설정의 서버명·활성화·URL 확인, 설치된 Codex CLI MCP 도움말 실행 시도.
- 최종 해결책: Codex 앱의 Settings → MCP servers → Apify에서 `Authenticate`를 실행하고 브라우저 인증을 완료한 뒤 MCP 서버 또는 앱을 Restart해야 한다.
- 같은 문제가 재발할 때 확인할 항목: `/mcp`에서 Apify가 연결됨으로 표시되는지, 현재 작업에 Apify 도구가 노출되는지, 브라우저 OAuth 완료 후 앱을 재시작했는지.
