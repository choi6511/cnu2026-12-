## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 설치 가능한 manifest·아이콘·Service Worker와 장소 소개·인증·도감의 제한적 오프라인 기반을 구현한다.

## 3. 구현 판단

- 선택한 구조 또는 접근: 추가 PWA 라이브러리 없이 `public/sw.js`와 App Router metadata route를 사용했다. Service Worker는 같은 출처의 정적 항목만 다루고, 설치 시 각 알려진 경로의 HTML에서 Next static asset URL을 추출해 함께 캐시한다.
- 대안과 선택 이유: 모든 same-origin GET를 캐시하는 방식은 App Router의 `?_rsc` 응답을 문서 응답과 섞을 위험이 있어 사용하지 않았다. RSC, Next image 최적화, `/api/**`, 카카오맵·Supabase 등 cross-origin 요청을 명시적으로 제외했다.
- PRD 또는 기존 구현과의 관계: 사진과 도감은 계속 IndexedDB에만 남고 서버·외부 캐시로 전송하지 않는다. 지도와 공지는 오프라인에 캐시하지 않으며, 공지는 전용 안내만 보여 준다.

## 4. 문제 및 막힌 지점

- 증상: 초기 Service Worker는 route HTML·이미지만 precache해, 처음부터 오프라인일 때 route-specific Next JS/CSS가 없을 수 있었다. `ignoreSearch`는 RSC 요청에 잘못된 캐시를 돌려줄 위험도 있었다.
- 재현 방법: Service Worker 설치 후 아직 열지 않은 도감·장소 경로를 오프라인에서 열거나, App Router의 `_rsc` 요청을 query 무시 캐시로 처리한다.
- 원인: Next.js App Router는 HTML 외에 해시된 static chunk와 RSC 요청을 사용한다.
- 영향을 받은 범위: 도감 hydration·IndexedDB 렌더링과 공지 화면의 오프라인 정확성.

구현을 중단시킨 문제는 없었음. 다만 현재 Codex 브라우저 런타임은 `navigator.serviceWorker`를 제공하지 않아 실제 worker 활성화·네트워크 차단 검증을 수행할 수 없었다. 친구 계정의 Vercel Hobby 프로젝트에는 팀 대시보드 권한도 없어 HTTPS Chrome 설치 검증이 남아 있다.

## 5. 해결 방법

- 시도한 방법: 처음에는 route 문서와 이미지 목록만 `cache.addAll`로 저장했다.
- 최종 해결책: route HTML에서 `/_next/static/` script/style URL을 추출하여 설치 시 함께 저장하고, navigation은 정확한 request key로만 fallback한다. 공지 navigation은 cache에 쓰지 않고 `offline-notices.html`을 반환한다. offline Link는 document navigation으로 전환해 cached route를 열며, worker 업데이트는 `skipWaiting`/`clients.claim` 없이 다음 안전한 reload 시 활성화한다.
- 같은 문제가 재발할 때 확인할 항목: offline cold-open과 offline Link 이동에서 collection·세 소개·세 verify route의 static chunks가 cache에 있는지, `_rsc`·`RSC` header·`/_next/image`가 cache에 들어가지 않는지, 공지 URL이 cache에 쓰이지 않고 항상 전용 offline message를 받는지 확인한다.

## 7. 미해결 사항 및 위험

- 남은 문제: 최근 공지 UI는 teammate가 병렬 구현했지만 Apify MCP 연결 전에는 실제 갱신 데이터가 없다.
- 임시 처리 또는 mock: 공지 화면은 빈·오류·오프라인 상태를 보이며, offline navigation에서는 정적 안내 페이지를 표시한다.
- 외부 키·계정·콘텐츠 의존성: 친구가 GitHub PR을 merge해 Vercel production에 배포한 뒤, 모바일 Chrome에서 설치와 offline test를 해야 한다. Vercel token이나 account access를 요구하지 않는다.
- 다음 작업에 영향을 줄 위험: Next.js chunk HTML 구조가 크게 바뀌면 `getStaticAssetPaths` 추출 결과를 재검증해야 한다. Browser data 삭제/앱 제거 시 IndexedDB 도감은 사라지는 기존 제한도 유지된다.
