## 3. 구현 판단

- 선택한 구조 또는 접근: AGENTS.md의 필수 도구 규칙에 따라 Vercel 플러그인에서 실제 팀과 프로젝트를 우선 확인했다.
- 대안과 선택 이유: 로컬/CLI 배포로 우회하지 않았다. 최종 배포 증거는 반드시 Vercel 플러그인으로 남겨야 하며, 빈 파일 목록으로 새 프로덕션 프로젝트를 만들면 정상 앱을 보장할 수 없기 때문이다.
- PRD 또는 기존 구현과의 관계: 배포 환경에는 공개 카카오맵 키 `NEXT_PUBLIC_KAKAO_MAP_KEY`만 넣고, 인증사진과 비밀키는 브라우저 번들·저장소에 두지 않는 경계를 유지한다.

## 4. 문제 및 막힌 지점

- 증상: Vercel 플러그인에서 팀은 조회됐지만 프로젝트 목록이 비어 있고, 현재 작업 폴더에도 `.vercel/project.json`이 없다.
- 재현 방법: Vercel 플러그인 `list_teams` 및 해당 팀의 `list_projects`, `Test-Path .vercel/project.json`을 실행한다.
- 원인: GitHub 저장소는 연결돼 있으나 이 앱에 대응하는 Vercel 프로젝트가 아직 생성·연결되지 않았다.
- 영향을 받은 범위: HTTPS URL, 배포 환경변수, 카카오맵 허용 도메인, 프로덕션 P0 흐름 검증을 수행할 수 없다.

Vercel 플러그인에서 빈 `files` 배열을 가진 production 배포를 시도했을 때 안전 정책이 이를 차단했다. 이는 새/기존 프로덕션 사이트를 빈 파일로 생성·교체할 위험이 있기 때문이며, 정상 앱 파일을 전달하지 않은 상태에서 재시도하지 않았다.

## 5. 해결 방법

- 시도한 방법: Vercel 플러그인으로 팀(`choi6511's projects`)과 프로젝트를 조회하고 production 배포 입력을 확인했다.
- 최종 해결책: 없음. 유효한 앱 파일이 포함된 배포 또는 GitHub–Vercel 프로젝트 연결을 명시적으로 승인·구성한 뒤에만 재개한다.
- 같은 문제가 재발할 때 확인할 항목: Vercel 프로젝트가 존재하는지, `.vercel/project.json`의 project/org ID가 실제 프로젝트와 맞는지, production 환경변수에 `NEXT_PUBLIC_KAKAO_MAP_KEY`가 설정됐는지, 배포 파일 목록이 비어 있지 않은지 확인한다.
