## 3. 구현 판단

- 선택한 구조 또는 접근: 장소별 소개 정보를 `places.ts`에 두고 소개 페이지는 이를 읽는 React Server Component로 유지했다. 외부 fetch나 클라이언트 상태를 추가하지 않아 세 경로가 빌드 시 SSG로 생성된다.
- 대안과 선택 이유: 페이지마다 문구를 직접 작성하는 방식은 장소 ID와 링크·자산의 불일치 위험이 있어 사용하지 않았다. `Place` 제네릭 타입을 확장해 이미지 경로와 장소 ID의 기존 타입 관계도 유지했다.
- 이미지 처리: 현재 대표 이미지는 W01에서 만든 규격 동일 임시 WebP이므로 `placeImageStatus: "placeholder"`를 데이터에 명시하고 화면에도 `임시 대표 이미지 · 실제 장소 사진으로 교체 예정`을 표시했다. 최종 사진으로 오인시키지 않았다.
- 정보 근거: 중앙도서관의 역할과 대덕캠퍼스 중앙 위치는 충남대학교 70년사 및 도서관 층별 안내, 국제언어교육센터의 역할·주소·E1-1 코드는 센터 공식 사이트와 충남대학교 캠퍼스맵, 산학연교육연구관의 W1 코드와 정류장 정보는 충남대학교 캠퍼스맵·셔틀버스 안내에서 확인했다.
- 확인한 공식 출처:
  - `https://plus.cnu.ac.kr/Upl/kr/70y/15.pdf`
  - `https://library.cnu.ac.kr/webcontent/info/326`
  - `https://dream.cnu.ac.kr/contents/eng_02_3.php`
  - `https://plus.cnu.ac.kr/html/cyber/cyber.html`
  - `https://plus.cnu.ac.kr/html/kr/sub05/sub05_050403.html`
- PRD 또는 기존 구현과의 관계: W01의 세 장소 allowlist, 정적 경로, 로컬 자산 경로를 그대로 사용했다. PRD의 지도·검증 기능을 선행 구현하지 않고 W02의 콘텐츠 화면과 후속 기능용 명시적 슬롯만 추가했다.

## 4. 문제 및 막힌 지점

- 증상: 최초 린트에서 `PLACE_IMAGE_SIZE` 미사용 경고 1건이 발생했다.
- 재현 방법: 첫 구현 직후 `npm run lint` 실행.
- 원인: `next/image`에 `fill`을 사용하면서 가져온 실제 이미지 규격 상수를 전달하지 않았다.
- 영향을 받은 범위: 런타임 오류는 없었지만 경고 없는 완료 게이트를 충족하지 못했다.
- 추가 도구 경계: Windows PTY에서 개발 서버에 보낸 첫 종료 신호가 적용되지 않았다. 포트 3000의 리스닝 PID와 시작 시각을 확인해 이번 세션에서 시작한 Node 프로세스만 종료했다.

## 5. 해결 방법

- 시도한 방법: 이미지 래퍼의 비율은 유지하면서 `next/image`에 1200×800 실제 크기를 전달하도록 변경했다.
- 최종 해결책: `width={PLACE_IMAGE_SIZE.width}`와 `height={PLACE_IMAGE_SIZE.height}`를 지정하고 CSS에서 반응형 너비를 적용했다. 이후 린트는 경고 없이 통과했다.
- 서버 종료: `netstat -ano`와 `Get-Process`로 포트 3000의 Node PID 26512 및 이번 검증 시작 시각을 확인한 후 해당 PID만 종료했고 `PORT_CLOSED`를 확인했다.
- 같은 문제가 재발할 때 확인할 항목: 로컬 이미지에는 실제 픽셀 크기와 `sizes`를 함께 전달하고, 브라우저 검증 종료 뒤 포트가 닫혔는지 확인한다.

## 7. 미해결 사항 및 위험

- 남은 문제: PRD의 최종 장소 소개 문구와 실제 대표 사진은 사용자 확인·제공이 필요하다. 현재 문구는 공식 자료에서 확인 가능한 사실에 한정했다.
- 임시 처리 또는 mock: `public/places/*.webp` 3개는 건물 사진이 아닌 명시적 임시 이미지다. 최종 사진을 받을 때 같은 경로·비율로 교체하고 `placeImageStatus`와 캡션을 제거하거나 실제 상태 모델로 변경해야 한다.
- 외부 키·계정·콘텐츠 의존성: W02 자체는 없음. 다음 W03은 `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`와 세 장소의 검증된 위도·경도가 필요하다.
- 다음 작업에 영향을 줄 위험: 좌표를 추측하면 방문 인증 정확도까지 연쇄적으로 훼손된다. 공식 지도 또는 사용자 확인을 통해 좌표를 확정하기 전에는 실제 좌표로 표시하지 않는다.
