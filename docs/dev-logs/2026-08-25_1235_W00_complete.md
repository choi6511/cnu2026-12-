## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 실행 가능한 Next.js App Router + TypeScript 골격, 타입 검사·린트·빌드 명령, 안전한 환경변수 경계와 기본 페이지
- 실제로 완료한 범위: 기존에 초안으로 놓여 있던 W00 파일을 실제 설치·실행 가능한 상태로 완성하고, Next.js 16.3.2/React 19.2.8 의존성 및 lockfile을 추가했다. 공개 환경변수와 서버 비밀 환경변수 모듈을 분리하고 `server-only` 경계를 적용했다. 기본 페이지의 브라우저 렌더링까지 검증했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 세 장소 정적 데이터, 전체 라우팅 골격, 하단 내비게이션과 임시 자산은 W01 범위로 남겼다. Vercel 배포, Supabase 변경, Octoparse 실행은 W00 완료 조건이 아니므로 수행하지 않았다.

## 3. 구현 판단

- 선택한 구조 또는 접근: `src/app` 기반 App Router를 사용하고 브라우저 공개 설정과 서버 비밀 설정을 서로 다른 모듈에 뒀다. 비밀 모듈은 `import "server-only"`로 빌드 경계를 강제했다.
- 대안과 선택 이유: 모든 환경변수를 한 모듈에서 읽는 방식은 Client Component의 우발적 import로 secret이 번들 경계에 접근할 위험이 있어 사용하지 않았다. W00에서는 값 누락 시 앱 전체를 즉시 중단시키지 않고 각 기능이 실제 키를 요구하는 W03/W09에서 사용자 친화적인 누락 상태를 처리하도록 했다.
- PRD 또는 기존 구현과의 관계: 로그인·사진 업로드·크롤러·자동 예약을 추가하지 않았고, `SUPABASE_SECRET_KEY`와 `OCTOPARSE_API_KEY`에는 `NEXT_PUBLIC_` 접두사를 사용하지 않았다.
- Next.js 스킬 적용 영향: 설치 버전과 일치하는 로컬 Next.js 16.3 문서를 확인해 `next-env.d.ts`는 Git에서 제외하고 `npm run typecheck`가 먼저 `next typegen`을 실행하도록 구성했다. 기존 `AGENTS.md`가 개발 서버에 의해 자동 변경되지 않도록 공식 `agentRules: false` 옵션을 적용했다.

## 4. 문제 및 막힌 지점

- 증상: 세션 시작 시 `package.json`의 dependencies/devDependencies가 모두 비어 있고 `package-lock.json`, `node_modules`가 없어 어떤 명령도 실행할 수 없었다.
- 재현 방법: `Get-Content package.json`, `Test-Path node_modules`, `Test-Path package-lock.json`으로 확인했다.
- 원인: W00 파일 초안은 있었지만 패키지 설치와 검증이 아직 수행되지 않은 상태였다.
- 영향을 받은 범위: 설치 전에는 개발 서버, 타입 검사, 린트, 빌드와 브라우저 검증을 수행할 수 없었다.

추가로 첫 `npm install`은 샌드박스의 npm 캐시/네트워크 접근 제한 때문에 `EACCES`로 실패했다. 권한 승인을 받은 동일 명령으로 재실행해 해결했다. 첫 린트는 수정 대상이 아닌 `CHA-CHA)Design System` 생성 번들까지 검사해 경고 26건과 약 90초 지연이 발생했다.

## 5. 해결 방법

- 시도한 방법: 런타임 의존성과 개발 의존성을 구분해 설치하고, 타입 검사·린트·빌드를 단계별로 실행했다. 개발 서버를 띄운 뒤 agent-browser로 DOM, 오류 오버레이, 스크린샷과 HTTP 응답을 확인했다.
- 최종 해결책: 승인된 npm 설치로 lockfile을 생성했고, 공식 디자인 시스템 폴더를 ESLint 전역 제외에 추가했다. `next typegen && tsc --noEmit`으로 새 환경에서도 생성 타입을 준비하도록 했다.
- 같은 문제가 재발할 때 확인할 항목: Node/npm 버전, npm 레지스트리 접근 권한, `package-lock.json`과 `node_modules` 일치 여부, 린트가 공식 참고 자산을 다시 포함하는지 확인한다. Next.js를 업그레이드하면 `node_modules/next/dist/docs/`의 설치 버전 문서를 먼저 확인한다.

## 7. 미해결 사항 및 위험

- 남은 문제: W00 범위의 미해결 구현은 없다.
- 임시 처리 또는 mock: 홈 화면은 W00 상태를 설명하는 최소 임시 화면이며 W01의 지도 앱 셸로 교체될 예정이다.
- 외부 키·계정·콘텐츠 의존성: 카카오맵 키·좌표·콘텐츠는 아직 W03 준비 사항이다. Vercel 프로덕션 배포는 W08, Supabase 앱 통합은 W09, Octoparse는 W10–W11에서 해당 플러그인으로 검증해야 한다.
- 다음 작업에 영향을 줄 위험: 현재 작업 트리에는 이번 W00 외에도 사용자가 먼저 만든 문서·ERD·디자인 시스템 변경이 함께 존재한다. 후속 작업은 이 변경을 덮어쓰거나 되돌리지 않아야 한다.
- 도구 제약: 로컬 `agent-browser` 실행 파일이 없어 `npx --yes agent-browser@latest` 0.34.0을 일회성으로 사용했다. 브라우저 검증 후 세션과 개발 서버는 종료했다.
