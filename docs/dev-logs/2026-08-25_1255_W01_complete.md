## 3. 구현 판단

- 선택한 구조 또는 접근: 장소 데이터는 `src/data/places.ts` 한 파일을 단일 기준으로 사용했다. `definePlace<Id>()`가 장소 ID와 `/places/<id>.webp`, `/characters/<id>.webp` 경로의 일치를 컴파일 시점에 강제한다.
- 대안과 선택 이유: 각 페이지가 slug 목록을 따로 소유하는 방식은 네 번째 장소가 우발적으로 노출되거나 장소명이 엇갈릴 위험이 있어 사용하지 않았다. 동적 params를 런타임에 계속 허용하지 않고 세 정적 params 외 값은 404로 고정했다.
- PRD 또는 기존 구현과의 관계: 자연사박물관은 포함하지 않았고, 하단 메뉴는 `지도`와 `캐릭터 도감`만 제공했다. 로그인, GPS, 사진 저장, 공지 조회, 크롤링은 추가하지 않았다.
- 디자인 시스템 적용 영향: 네이비 `#002D72`, 티얼 `#009AB0`, 밝은 중립 배경, 평면 색상, 둥근 카드, 2px 선형 UI 아이콘을 사용했다. 이모지와 그라데이션은 사용하지 않았다. 공식 마스코트 원본은 변형하지 않았고 임시 캐릭터 파일은 `TEMP`가 표시된 비브랜드 실루엣으로 구분했다.
- Next.js/React 스킬 적용 영향: Next.js 16의 비동기 `params`를 모두 `Promise`로 타입 지정해 await했고, `generateStaticParams`와 `dynamicParams = false`를 `[slug]` 레이아웃에 모았다. Client Component는 `usePathname`이 필요한 하단 내비게이션 하나로 제한했다.

## 4. 문제 및 막힌 지점

- 증상 1: 첫 타입 검사에서 `Object.fromEntries`가 세 장소 키의 완전성을 증명하지 못해 TS2352가 발생했다.
- 원인: 반환 타입이 일반 문자열 키 객체로 추론되어 `Record<PlaceId, Place>`의 세 키가 모두 있다고 보장할 수 없었다.
- 해결 영향: 장소 조회 인덱스를 `Map<PlaceId, Place>`로 바꿔 단언 없이 통과시켰다.

- 증상 2: WebP 생성 시 fontconfig의 쓰기 가능한 캐시 디렉터리가 없다는 경고가 발생했다.
- 원인: Sharp가 SVG의 시스템 글꼴을 확인하는 과정에서 샌드박스 밖의 글꼴 캐시에 쓸 수 없었다.
- 해결 영향: 생성 프로세스는 exit 0이었고 이후 Sharp metadata로 6개 파일의 형식과 크기를 재검증했다. 텍스트는 일반 Arial 폴백으로 정상 생성됐다.

- 증상 3: 개발 서버에서 아직 컴파일되지 않은 10개 경로를 동시에 `fetch`한 첫 검사 중 `/places/industry-center` 한 건이 500과 `Unexpected end of JSON input`을 반환했다.
- 원인: 같은 slug의 공지·인증 화면과 프로덕션 정적 빌드는 정상이고, 해당 소개 화면을 직접 연 뒤 즉시 200으로 복구되어 Turbopack 개발 서버의 동시 최초 컴파일 중 일시 상태로 판단했다.
- 해결 영향: 모든 경로를 순차 요청해 9개 정상 경로 200, 잘못된 slug 404를 다시 확인했다. 이후 브라우저 오류 오버레이와 콘솔 오류도 없었다.

- 증상 4: agent-browser의 `@e4` 참조를 PowerShell이 변수로 해석해 첫 메뉴 클릭 명령이 실행되지 않았다.
- 원인: 요소 참조를 따옴표 없이 명령 인자로 전달했다.
- 해결 영향: `"@e4"`처럼 문자열로 전달해 도감↔지도 클릭 이동을 정상 검증했다. 앱 코드 결함은 아니었다.

## 5. 해결 방법

- 시도한 방법: 타입 검사와 린트를 먼저 실행하고, 프로덕션 빌드로 모든 정적 경로 생성을 확인한 뒤 agent-browser에서 320×800 viewport로 홈·장소·도감·404를 검증했다.
- 최종 해결책: 상위 동적 레이아웃에 장소 검증을 집중하고, 각 페이지는 `resolvePlace()` 결과만 사용하도록 했다. 장소 ID 인덱스는 타입 안전한 Map을 사용했으며, 브라우저 경로 검사는 동시 요청이 아닌 순차 요청으로 재확인했다.
- 같은 문제가 재발할 때 확인할 항목: 새 장소를 임의로 추가하지 말고 PRD 변경 여부를 먼저 확인한다. 경로가 500이면 `npm run build`의 SSG 결과, 직접 브라우저 요청, `.next/dev/logs/next-development.log`를 함께 비교한다. PowerShell에서 agent-browser의 `@ref`는 반드시 따옴표로 감싼다.

## 7. 미해결 사항 및 위험

- 남은 문제: W01 범위의 미해결 구현은 없다.
- 임시 처리 또는 mock: 장소 이미지와 캐릭터 이미지는 모두 기능 개발용 임시 WebP다. 캐릭터 파일은 공식 차차 파생 이미지가 아니며 발표용 최종 자산으로 사용하면 안 된다.
- 외부 키·계정·콘텐츠 의존성: 실제 장소 소개·위치·대표 이미지는 W02, 정확한 카카오맵 좌표와 키는 W03에서 필요하다. 캐릭터 파생 제작 권리와 최종 이미지 3개는 W06 전까지 사람이 확인해야 한다.
- 다음 작업에 영향을 줄 위험: `public/characters/<id>.webp`의 파일명과 1024×1024 비율을 유지해야 후속 코드 수정 없이 최종 자산을 교체할 수 있다. 장소 이미지도 `/public/places/<id>.webp` 경로를 유지한다.
- 운영 환경 위험: 동시 미컴파일 경로 요청에서 개발 서버 일시 500이 한 번 있었으나 순차 재검증과 프로덕션 빌드는 모두 통과했다. 프로덕션 배포에서는 W08 브라우저 검증으로 다시 확인한다.
