## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 장소 소개의 획득 상태 원에 캐릭터 도감과 같은 장소별 차차 이미지를 표시한다.
- 실제로 완료한 범위: 상태 원의 별도 WebP 자산 렌더링을 도감과 동일한 `ChachaMascot` 및 장소별 variant 매핑으로 교체했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 획득 판정, IndexedDB 기록 형식, 도감 카드와 인증사진은 변경하지 않았다.

## 3. 구현 판단

- 선택한 구조 또는 접근: 도감 카드가 이미 사용하는 `mascotVariantForPlace(placeId)` 매핑을 상태 원에서도 재사용했다.
- 대안과 선택 이유: 장소별 WebP 파일을 도감 쪽으로 바꾸지 않았다. 도감의 실제 표시 기준을 상태 카드가 그대로 따르는 편이 자산 불일치를 없애고 변경 범위도 가장 작다.
- PRD 또는 기존 구현과의 관계: 캐릭터 획득 여부는 계속 IndexedDB 레코드만으로 판정하며 서버 저장이나 새 보상 기능을 추가하지 않았다.

## 4. 문제 및 막힌 지점

- 증상: 획득 상태 원에는 `/public/characters/*.webp`가 보이지만 사용자가 원하는 도감 카드의 차차 그림과 달랐다.
- 재현 방법: 장소 방문 인증 후 장소 소개와 `/collection` 도감의 캐릭터 그림을 비교한다.
- 원인: 두 화면이 서로 다른 이미지 소스를 사용했다.
- 영향을 받은 범위: 장소 소개 화면의 획득 완료 상태 카드.

## 5. 해결 방법

- 시도한 방법: 도감 구현과 상태 카드 구현의 캐릭터 이미지 렌더링 경로를 비교했다.
- 최종 해결책: 상태 카드의 이미지 경로 prop을 제거하고 도감과 같은 `ChachaMascot` 컴포넌트를 사용했다.
- 같은 문제가 재발할 때 확인할 항목: 장소별 캐릭터를 추가하거나 변경할 때 `PLACE_MASCOT_VARIANTS`를 갱신하고 두 화면에서 동일한 variant를 사용하는지 확인한다.
