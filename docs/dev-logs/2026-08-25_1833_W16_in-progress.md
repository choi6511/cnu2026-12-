# 개발일지 — W16 선택 개선: 시네마틱 프론트엔드

## 1. 작업 개요

- 사용자 요청: 기능 중심의 현재 화면을 차차 브랜드 시스템을 기준으로 한 시네마틱 모바일 경험으로 재구성한다.
- 이번 범위: 홈 탐방 진입부, 세 장소 선택 카드, 지도 섹션, 장소 소개, 도감, 하단 내비게이션의 시각 계층·반응형·모션을 개선한다.
- 범위 제외: 카카오 지도 데이터, Supabase 공지 조회, IndexedDB 획득 로직, 사진 처리, PWA 캐시 책임과 API 계약은 바꾸지 않는다.

## 2. 변경 사항

| 파일 | 변경 | 이유 |
| --- | --- | --- |
| `src/app/page.tsx` | 사진 기반 hero, 차차 마스코트, 세 개의 scene 카드와 지도 흐름으로 재구성 | 지도 이전에 탐방 동기를 만드는 시네마틱 진입 경험을 제공한다. |
| `src/app/places/[slug]/page.tsx` | 장소 사진 위 scene label·제목 레이어와 상세 화면 계층을 추가 | 장소 소개가 탐방 흐름의 한 장면으로 이어지게 한다. |
| `src/app/collection/page.tsx` | 도감 헤드라인을 탐방 기록 중심으로 변경 | 획득 데이터를 유지한 채 수집 경험을 강조한다. |
| `src/app/globals.css` | 브랜드 토큰을 활용한 깊이·사진 scrim·CSS perspective·모바일 반응형·reduced-motion 규칙을 추가 | 별도 3D 런타임 없이 PWA 성능을 보존하면서 입체적이고 영화적인 인상을 만든다. |

## 3. 구현 판단

- `CHA-CHA)Design System/readme.md`의 캐릭터 자산, navy/teal/white palette, 사진 위 scrim 허용 규칙, 작고 빠른 모션 규칙을 따랐다.
- 실제 Three.js 장면을 추가하지 않았다. 이 MVP는 카카오 지도·카메라·오프라인 캐시가 이미 핵심이며, 무거운 WebGL 의존성보다 CSS perspective와 제공된 마스코트/장소 사진의 다층 구성이 초기 로드와 PWA 안정성에 적합하다.
- 홈의 장소 카드와 기존 경로(`/places/[slug]`, `/collection`)를 유지해 backend 및 기존 브라우저 저장 기능의 계약을 바꾸지 않았다.

## 4. 문제 및 해결

- 문제: 기존 배포는 설치·오프라인 기반만 추가됐고, 사용자가 합의한 프리미엄 시네마틱 프론트엔드로 오인될 수 있었다.
- 해결: PWA 변경과 시각 재설계를 분리하고, 이번 작업을 별도 `feature/cinematic-frontend` 브랜치에 둔다.
- 문제: 로컬 preview server와 Next production build가 같은 `.next` lock을 사용했다.
- 해결: 직접 시작한 preview server만 종료한 뒤 clean build를 다시 실행했다. 외부 서비스나 사용자 프로세스는 건드리지 않았다.

## 6. 미해결 사항 및 위험

- 이번 결과는 고품질 CSS 3D/perspective 연출이며, WebGL 기반의 실시간 3D 캠퍼스 모델은 아니다. 실제 3D 모델 제작은 별도의 자산·성능 예산·사용자 승인이 필요하다.
- Vercel production에는 아직 이 브랜치가 병합되지 않았으므로 현재 public URL은 이전 UI를 제공한다.
- W15가 완료되지 않은 상태에서 사용자 요청으로 W16 성격의 독립 시각 개선을 먼저 수행했다. P0 탐방 흐름의 동작을 변경하지 않았다.
