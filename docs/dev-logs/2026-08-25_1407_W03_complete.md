## 1. 작업 개요

- 이번 작업 단위에서 만들기로 한 것: 활성화된 Kakao 지도 API로 실제 지도 타일과 세 고정 마커를 표시하고, 각 마커·라벨의 장소 소개 이동 및 모바일·실패 경로를 검증해 W03을 완료한다.
- 실제로 완료한 범위: Kakao SDK HTTP 200 응답, 충남대학교 캠퍼스 지도 타일, 세 장소 마커·라벨, 각 마커와 라벨의 올바른 상세 이동을 실제 브라우저에서 확인했다. 320×800 환경의 가로 넘침과 중앙 상태 배지가 장소 클릭을 가로채는 문제도 수정했다.
- 범위에서 제외하거나 다음으로 넘긴 것: 프로덕션 도메인 등록과 배포 URL 검증은 W08 Vercel 배포에서 수행한다. GPS 기반 현재 위치, 자동 위치 추적, 지도 내 크롤링 기능은 PRD 범위 밖이므로 추가하지 않았다.

## 3. 구현 판단

- 선택한 구조 또는 접근: 기존 Server Component/Client Component 경계와 `next/script`의 `autoload=false` 흐름을 유지했다. 키 값은 출력하지 않고 존재 여부·길이와 SDK 응답 상태만 확인했으며, 성공 판정은 실제 지도 타일 DOM과 브라우저 클릭 결과로 했다.
- 대안과 선택 이유: 정적 지도 이미지나 mock 마커를 성공으로 취급하지 않았다. W03 완료 조건이 온라인 Chrome의 실제 Kakao 지도와 링크 동작을 요구하므로 인앱 Chromium에서 실제 SDK 타일·마커의 포인터 클릭을 검증했다.
- 클릭 문제 판단: 중앙도서관 라벨의 중심점에서 `document.elementFromPoint` 결과가 `.map-ready-badge`로 확인되어 단순 자동화 실패가 아니라 실제 겹침 문제로 확정했다. 상태 배지는 비조작 정보이므로 포인터 이벤트를 받지 않게 하고, Kakao 오버레이는 `clickable: true`로 지도 이벤트 전파 경계를 명시했다.
- PRD 또는 기존 구현과의 관계: 세 공식 좌표, `/places/<id>` 경로, 오프라인·SDK 오류 안내, 정적 장소 목록 fallback, GPS 미사용을 모두 유지했다.

## 4. 문제 및 막힌 지점

- 증상: API 활성화 후 지도와 라벨은 표시됐지만 중앙도서관 라벨을 실제 포인터로 눌러도 홈 화면에 머물렀다. 320px 검증에서는 15px의 가로 넘침도 감지됐다.
- 재현 방법: 라이브 Kakao 지도를 연 뒤 라벨 중심 좌표를 클릭하고 URL을 확인했다. 같은 좌표의 최상단 요소를 조사하자 `map-ready-badge`였고, 모바일에서는 `innerWidth=320`, 스크롤바를 제외한 `clientWidth=305`인데 `html` 최소 너비가 320px로 고정되어 있었다.
- 원인: 준비 완료 배지의 높은 z-index와 기본 포인터 이벤트가 중앙 라벨 위에서 클릭을 가로챘다. 또한 `html { min-width: 320px; }`가 고전 스크롤바 환경의 실제 콘텐츠 폭 305px보다 넓어 가로 스크롤을 만들었다.
- 영향을 받은 범위: 중앙도서관 지도 진입과 폭 320px 브라우저의 레이아웃에 한정됐다. 국제언어교육센터·산학연교육연구관 데이터와 경로, 오류·오프라인 상태에는 영향이 없었다.

## 5. 해결 방법

- 시도한 방법: 접근성 locator 클릭과 실제 포인터 클릭을 반복하고, 라벨의 bounding rectangle 및 해당 중심점의 hit-test 체인을 확인했다. 이후 CSS와 Kakao 오버레이 옵션을 수정하고 라벨 3개와 마커 아이콘 3개를 각각 다시 눌렀다.
- 최종 해결책: `.map-ready-badge`를 포인터 입력에서 제외하고, CustomOverlay를 클릭 가능한 오버레이로 명시했으며, `html`의 고정 최소 너비를 제거했다. 최소 Kakao 타입 선언에도 같은 옵션을 반영했다.
- 검증 중 발생한 타입 오류: 첫 타입 검사에서 로컬 최소 선언에 `clickable`이 없어 TS2353이 발생했다. `src/types/kakao-map.d.ts`의 옵션 계약을 보완한 뒤 재실행하여 통과했다.
- 같은 문제가 재발할 때 확인할 항목: 지도 요소의 시각적 위치만 보지 말고 `elementFromPoint`로 실제 hit target을 확인한다. 상태 배지·오버레이의 z-index와 pointer-events, Kakao CustomOverlay의 클릭 옵션, 브라우저 스크롤바를 제외한 `clientWidth`를 함께 점검한다.

## 7. 미해결 사항 및 위험

- 남은 문제: W03 범위의 미해결 기능은 없다. 프로덕션 Vercel URL이 결정되면 Kakao JavaScript SDK 허용 도메인에 해당 HTTPS origin을 추가해야 한다.
- 임시 처리 또는 mock: 없음. 성공 검증은 실제 Kakao SDK와 지도 타일로 수행했다.
- 외부 키·계정·콘텐츠 의존성: Kakao 앱의 지도 API 활성 상태와 허용 도메인이 필요하다. 공개 JavaScript 키라도 Git에는 저장하지 않고 `.env.local` 또는 배포 환경변수로만 관리한다.
- 다음 작업에 영향을 줄 위험: 지도 상단 상태 배지와 중앙 마커가 가까우므로 향후 지도 높이·좌표·배지 크기를 바꾸면 hit target 회귀를 다시 확인해야 한다.
